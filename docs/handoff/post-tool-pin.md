## How to use it (the next review)

1. In the release tree: `node tools/continuity-id.mjs` and put the line in the report's notes.
2. Run the harness from that tree (`node critic/runner/lib/continuity.mjs ... --candidate-root=<the candidate's tree>` when the candidate is another tree).
3. `node tools/continuity-id.mjs --check <evidence>/continuity-summary.json` (exit 0).
4. Once the report file is written: `node tools/continuity-id.mjs --embed <evidence>/continuity-summary.json --into <report.json>` in the release tree (copies the summary and its stamp into `report.continuity` verbatim and asks the rule; exit 0). Nobody retypes the stamp.
5. `node tools/critic-score.mjs --report <abs path>` and `node tools/critic-clear.mjs --report <abs path> --records <the tree that holds critic/pending>` **from the release tree** (its code and policy judge the report; `--records` is only needed when the records live in another tree, MAIN in the runner flows). `--harness-tree <dir>` stays for the case where the release tree is behind the clean tree that ran the harness; the tools print a NOTE when it is used.
