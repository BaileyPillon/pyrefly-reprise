## 4. The end wait (FFX-2 only)

**The find** (RE's rc8 check, handoff item 7 of the X2 lane): after the last blow the HUD shows an empty command window and a clock that keeps running for 1.5 to 4.5 s (3 s on every Chapter XIII loss) while the spells in flight finish.
**The cause:** RE's commit window stopped the engine from building the result on the last blow; the HUD took its menu down on "a `ko` played while the state already carries the result" (`ui/ffx2/fightDecided.ts`), which was the last blow, and with the window the state carries no result until the end of the wait. So the command window, the advisor and the help line stayed up for a menu whose owner can no longer act (`inputValid` is false), and the party's ATB bars went on counting: a girl whose cast had just fired filled to READY and shimmered. "The clock" is that: the gauges counting toward turns that cannot come; the HUD has no other visible clock.
**The change:** the engine keeps a flag on the state it already hands the HUD (`BattleState.flags.endWindow`, `battle/ffx2/end-flag.ts`; set on the step the window opens, kept once the end is committed, taken off if a revive lapses it). No shared contract changes, no event or random number is added, no golden moves. `fightDecidedBy` treats a `ko` under the flag as the last blow again; `FFX2BattleHud.sync` treats the flag like a result (menu, reticle and banners down); `ui/ffx2/endHold.ts` draws a bar that is not charging as it first stood in the ending and not ready, while a charging bar (a spell in flight) runs to the end of its cast. Nothing is added to the screen. FFX is untouched (no commit window, no ATB bar, no flag).
**Measured** (Chapter IV, the shipped line at fast speed, 1600x900, seed 1, a headless browser, the window's samples every 60 to 150 ms): **before** (this tree without the change): 13 samples over 1.98 s, the command window up in **13 of 13**, Rikku's bar 100% and READY while Yuna's and Paine's casts ran to 88% and 82%; **after** (the final build): 8 samples over 1.72 s, the command window up in the first sample only and **closed from the second (0.57 s after the window opened) to the end**, Rikku's bar 100% and not READY, the two casts running to the same 88% and 82%, the result a victory in both; an earlier run on the second build (the end wait code is the same) sampled finer, 16 samples over 1.65 s, up in the first 4 (about half a second, until the HUD takes the last blow's KO) and closed in the other 12. Frames: the end wait before and after.
**Tests:** `tests/unit/ffx2-end-wait-hud.test.ts` (15): the flag's life (set at the window, kept at the commit, off at a lapse, on again at the next end), `fightDecidedBy`, `EndHold`, and the real HUD with a real engine state (the command window closes at the last blow's KO and at the next sync; the control: an ordinary KO leaves it up; the bars; the Chapter XIII loss's wait). The production edits taken out fail 7 of the first 14.
**Not walked:** a Chapter XIII loss in a browser (the rule is the same: the last girl's KO takes the menu down; the unit test plays it with the real engine).
