## 4. How a release tree gets the models into `public/models-exp`

The models are gitignored (the repo is public) and local only, like `public/art`. A clean release tree (`D:\pyrefly-release`) has no `public/models-exp`, and `D:\pyrefly-release\public` today holds `art`, `audio`, `fonts` and nothing of the models. Both sets are on this disk and were verified read-only in this pass: `yrp-models-verify --source` on `D:\pyrefly-yrp-real\public` **PASS, 43 files, 141.3 MiB**; `ww-models verify` on `D:\pyrefly-ww\public\models-exp\windwaker` and on the backup **PASS**.

**The Wind Waker set (11 files) is restored by the build itself.**
- Source: `D:\pyrefly-ww\public\models-exp\windwaker` is the working copy; **the backup** `D:/Tools/pyrefly-models-backup/windwaker` (override: `PYREFLY_WW_BACKUP`) is what the tooling restores from. The list of names, sizes and sha256 is committed: `tools/ww/ww-models.json` (11 files, 33,882,528 bytes = 32.31 MiB; largest `rikku.glb` 5.56 MiB).
- `vite build` runs the plugin `tools/vite-ww-models.mjs` (registered in `vite.config.ts` after the dist filter): in `configResolved` it runs `node tools/ww-models.mjs ensure --warn` (verifies `public/models-exp/windwaker`, copies what is missing or different from the backup, never deletes), and in `closeBundle` it checks the OUTPUT's `models-exp/windwaker` against the list. A **release build** (`PYREFLY_RELEASE` set: the deploy and a review's candidate always set it) that does not carry them intact **fails**; any other build warns. `predev` and `prebuild` also run `ensure --warn`.
- Env words: `PYREFLY_WW_MODELS=skip` turns both steps off (ships the chapter on capsules on purpose); `PYREFLY_WW_BACKUP=<dir>` changes the backup; `PYREFLY_RELEASE=<n>` makes the check fatal.
- Manual: `node tools/ww-models.mjs ensure` (or `restore`), then `verify`; the tool only copies.

**The 3D Bahamut's set (43 shipped files, from 97 + 43) is NOT restored automatically; the tree must be given it before the build.**
- Source: `D:\pyrefly-yrp-real\public\models-exp` (1,138 MB: `yrp/` and `yrp-hd/`), the only copy besides the extraction output (`D:/Tools/ffx-parity/assets/runtime/yrp-dress/` and `D:/Tools/pyrefly-scratch/2026-10-20/real-ffx2*`). A mirror and a backup like the art's are an open question (section 7).
- **Give the release tree the two folders as junctions, not the whole `models-exp` folder:** `public/models-exp` must be a real directory in the release tree so that `ww-models ensure` copies the Wind Waker files into the release tree and not into the yrp lane's tree. In PowerShell 7 (from `D:\pyrefly-release`):
  - `New-Item -ItemType Directory -Force public\models-exp`
