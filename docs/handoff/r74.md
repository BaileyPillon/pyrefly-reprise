- Source: `D:\pyrefly-ww\public\models-exp\windwaker` is the working copy; **the backup** `D:/Tools/pyrefly-models-backup/windwaker` (override: `PYREFLY_WW_BACKUP`) is what the tooling restores from. ### 9.3 The `three` from source plugin: why it is kept

`tools/vite-three-src.mjs` (70 lines) stays because all three conditions of the brief hold:

1. **Its shaders equal the stock build's.** `three` ships `src/` as one module per class, and its own build strips the comments and blank-line runs from the GLSL template strings of `src/renderers/shaders/**/*.glsl.js`; the plugin does the same (`minifyGlsl`). `tests/unit/vite-three-src.test.ts` runs the plugin over every one of those files, imports the result as a module, and proves (a) each string it produces is, as a JSON literal, present in the stock `three.core.js` or `three.module.js`, and (b) every `ShaderChunk` string, both stages of every `ShaderLib` program and a bare `ShaderMaterial`'s two defaults are produced by some source file (over 130 strings). A source that was not minified would differ, so the equality can fail. It passes.
2. **A production build with it and with the kill switch both succeed** on this tip: `build-on.log` and `build-off.log`, exit 0 for both, the same shipped file lists apart from `assets/*` and `index.html`; the build privacy gate (`node tools/dist-local-paths.mjs --dir <build>`) passes on the build with the plugin (1,409 text files: no local path, no claude.ai link, no sidecar key outside the list).
3. **Every test passes** (section 9.7).

What it changes in the build: one alias for the bare `three` (exact match: `three/addons/*` and `three/src/*` are left alone, so the addons' own `from 'three'` follows it and there is one copy), and the shader step on `three/src/**/*.glsl.js`. Nothing in `src/`.

### 9.5 The door suites' flake: found, and it was not the 219q gate

The first fix pass saw `tests/unit/angra-door.test.ts` fail with the 219q change ("keepeangra: expected [] to deeply equal [ 'ffx2-angra-mainyu' ]") and read it as a gate defect. It is not:

- **Evidence.** The test passes alone on the tree with the gate (this pass: 22 of 22, the pair case 18.5 s). On the 30 door files at 5 workers it failed five cases in one run (angra, summon, valefor, windwaker and yojimbo: `summoangra`, `yrpsummon`, `valeforyrp`, `keepewaker` and `yrp` alone, each expecting a chapter and getting none or the other word's), a different set in each run (the first pass's runs lost `yrangra`, `keeperdaigoro`, `wakersummon`, `summoangra`, `daigorokeeper` and `keepeangra`, one or two per run; its first run also failed `chapter-doors.test.ts`, which still expected one gated row: fixed with the gate, commit `1adab11b0`). `valeforyrp` loses VALEFOR, a door with no gate, so a gate cannot be the cause; `yrp` and `waker` are the last two rows of the table, so they are typed at the end of a loop with forty boards alive.
- **Cause.** The board's doors judge a typed word by the gap between its letters (`WordDoor`, `KEY_GAP_MS` = 2000 ms), and `ChapterSelectScreen` feeds them `performance.now()`: the wall clock. Every other part of a door suite runs on a fake frame clock. The loop cases ("each word opens its own chapter", "the first word to finish wins": up to forty-two real boards, each with its `Input`, alive until `afterEach`) type their words synchronously, so a word is stale only if the test process stalls for two seconds inside it (a major garbage collection with forty boards alive, a busy PC with five workers). A stalled word resets and nothing opens.
- **Fix.** `tests/unit/helpers/doorClock.ts` `useDoorClock()` replaces `performance.now` with a clock that moves one millisecond per read; the 22 loop cases of the 11 pairwise door suites call it (`vi.restoreAllMocks()` in each suite's `afterEach` puts the real clock back). The cases that are about the gap (a pause over 2 s) keep their own clock. Tests only; commit `6b5723df1`.
- **Proof.** The same 30 door files, `--maxWorkers=5`: before, 5 failed and 627 of 632 passed (193 s); after, 30 files and 632 of 632 passed (74 s).
