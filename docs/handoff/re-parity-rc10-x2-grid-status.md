## 1. The ten grids, what the notes say, and what is wired

The note lists the ten (`FFX2-G04` 3.4, **[data fact]**): "Highroad Winds (SOS Haste), Mounted Assault (Auto-Haste), Downtrodder (Double HP), Selene Guard (SOS Shell, Auto-Shell), Helios Guard (SOS Protect, Auto-Protect), Shining Mirror (Auto-Reflect), Wishbringer (Auto-Regen), Tempered Will (Double MP, Double HP), Peerless (Critical, Magic Booster, Break Damage Limit, Auto-Haste), Last Resort (Spellspring, Critical, Magic Booster, Break Damage Limit)".
Cross-checked against the repo's own plate table (`kernel/dressphere-grids.ts`, read through `applyAbilityEffects` for every pair of all 64 plates): **exactly the same ten plates** (9, 10, 15, 23, 24, 25, 33, 50, 62, 63). The engine's registry holds 44 of the 64 plates; **three of the ten are in it**.

How the game applies a grid's pairs (the rules this lane implements; labels as the notes give them):

* A plate row holds eight (condition, ability) pairs. **Condition 0 is always on** (listed as soon as the grid is worn; no mastery needed); **conditions 1 to 4 are one gate, 5 gates 1+2, 6 gates 3+4, 7 gates 1+2+3, 100 every gate, 101 every dressphere node worn, 102 both**, placed in the girl's eight gate slots when the gate evaluation (`0x005f4170`, run when a dress change lands) finds them crossed. `FFX2-G09` 3.5 **[emulated (4,173 + 6,000 vectors, 0 mismatches)]**; the pairs **[data fact]**. The game's list for a girl is, in order, her dressphere's rows, the gate slots, the grid's always-on pairs, then her accessories (`kernel/dressphere-abilities.ts#abilityList`, G04 3.3).
* An **ordinary row** fills the **kept** set (in the effective layer always; no clock; "Auto-" statuses carry the count 126, "permanent"). An **SOS row** (special bit 0) sets the SOS flag and fills the **SOS** set, which is in the effective layer **only while the HP state is 1** (`HP * 3 < max HP`, truncating, dead excluded). G04 3.2, 3.3, 3.4 **[emulated (89,184 vectors, 0 mismatches)]**; "State 2 (dead) and state 0 leave only the kept layer; SOS statuses vanish at once on a KO or a heal to a third or more."
* **Lost at a KO? Back at a revive?** The kept set is never lost; the SOS set vanishes at the KO and comes back through the SOS check after a result that leaves the state at 1 (a revive to under a third). **The gate progress itself is not cleared by a KO or a revive** and **every battle starts with no walk and no gate bonus** (`FFX2-G09` 3.6 **[emulated (200 vectors)]**).
* **Stacking with dresspheres and accessories**: one list, one table fill (`applyAbilityEffects`): bits OR, group 2 counts add saturating (the 126 of a permanent row stays 126); a row already in the list is not listed again unless its row is stackable (special bit 2). G04 3.2 **[emulated (5,816 vectors)]** for the add. A Haste Bangle beside Highroad Winds is the one row 0x8078.
* **A Dispel cannot take it** (G04 3.2: the kept and SOS layers are separate from the applied layer **[inferred from the layer split; consistent with the recorded wiki claims]**).

## 2. What the engine does now

| Piece | Where | What it is |
|---|---|---|
| The grid's rows | `adapt/auto-grid.ts` (84 lines) | `GridPlate` (the plate number, the colour each gate number wears, the card's gate numbers), `gateStateOf` (a gate number is crossed when its colour is; every gate crossed when each of the card's gate nodes is; "every dressphere node worn" is false because **no plate uses conditions 7, 101 or 102**, pinned over all 64 plates), `gateRows` (the kernel's `gateSlotsAfter` from empty slots: a walk only adds crossed gates, so no stale slot can be read), `plateRows` (the kernel's `plateAbilityGroup`), `keepsStatus` (only rows that keep a status or set an SOS set; a First Strike or a stat row would only build a layer with nothing in it) |
| Where it joins the list | `adapt/auto-layer.ts` | `AutoLoadout` (the shape both a unit and a member share), `autoRowsOf` (dressphere rows, gate rows, always-on rows, accessories: the game's order), `poolHolds` (rows 0x8098 / 0x8099 hold bits 0x800 / 0x1000 of the kept set) |
| The registry | `adapters.ts`, `adapt/grid-layout.ts`, `internal.ts` | `GarmentGridDef.gateRows` (optional, additive, from the layout's `plate` and `colourOfGate`); a grid with no layout lists none |
| The layer | `auto-layer.ts` | `LayerHost.grids`; `initAutoLayers` and `rebuildAutoLayer` pass the registry (`setup.ts`, `execute.ts`); everything else is the X2-D layer, unchanged |
| The pools | `kit.ts`, `spherechange.ts`, `setup.ts` | `withPoolStatuses(stats, statuses, held)`: the game's maximum recompute (`0x00636560`) reads one status bit for Double HP and one for Double MP, so a Stamina Tonic and a row together double **once**; MP is capped at 999 as the game's recompute caps it. `refreshDerivedStats` (every dress change) and `buildMember` (the start, for a carried walk) ask for the rows' answer **before** the stats are made |
| The switch | `constants.ts#GRID_AUTO_STATUS` | off, a grid lists no row, as every build before RC10 (the measurement and rollback switch; no random draw either way) |

**Why the maximum doubles in the very change that crosses the gate** (the one place the lane reads the game's code rather than a note's table): the dress change's refresh (live `0x625DE0`, **[read only]**) remembers HP, MP and the maxima, rebuilds the record, copies it, rebuilds the tables from the new ability list (which now holds the gate slots), runs the forced automatic copy and the status merge (`MsSetStatus`: the merged word ORs in the effective layer, `FFX2-G05`'s table "last step of `MsSetStatus`" is the maximum recompute), and only then puts HP and MP back from the remembered values with the ratio rule against the **new** maximum. So a girl at full HP who crosses the Double HP gate is at full doubled HP, and a wounded girl keeps her share. The engine's HP and MP scaling is its own existing ratio rule (`refreshDerivedStats`), unchanged. Label: the recompute function itself is in the audit's "Proven (64,900 vectors)" family (audit C14); the order inside the rebuild is **[read only]**; that the status word the recompute reads includes the effective layer is `MsSetStatus` **[read only]**, consistent with `research/re-ffx2-dressphere.md` 1.6.

## 5. Measurement

**Method.** `tests/unit/ffx2-grid-status-measure.test.ts` plays each chapter's whole chain with the shipped `intendedStrategy` through the app's own path (the same loop as `ffx2-parity-measure.test.ts` and the stat setter's measurement), on **two trees**: **base** is `origin/r52-rc` (`3c92b60cc`) and **after** is this branch at `b1890c219` (the code; the later commits are tests and this note), each extracted with `git archive` into a scratch folder under the lane's temp folder (nothing added to the worktree; `node_modules` by junction). Every row carries a digest of every event of every link in order, so two trees agree on a seed only when the fights are the same event for event, and counts what the lane's rows touched from the event logs. Paces (`PYREFLY_MEASURE_PACE`): **bench** is Wait, the shipped default, answering every menu at once (what every parity measure does); **human** is Wait's split with 1.5 s spent at each menu, 0.5 s of it on the top list (the PR-0076 bench's modelled human); **Active** is the Active clock with 1.5 s at each menu. The 1.5 s and 0.5 s are authored measurement inputs, not game data. Measure, never tune: nothing was adjusted to move a number.

### 5.3 The cause, in player words, with its ablations

* **Cause.** In these fights Yuna (Tempered Will) is hit with Itchy, and the autopilot's answer is her Change out of it, White Mage to Gunner, the first row of her Change menu. On Tempered Will that Change goes through the **red gate**, which keeps Double MP: from that Change on she shows "Max MP x2" and her MP bar is twice as long (full MP stays full). It does not change what she or the party does: **the intended play never runs short of MP**, so no choice, no draw and no number of the fight changes, and the only difference between the two logs is the one extra `status-add` event that announces the icon.
* **Ablation 1, the switch** (`constants.ts#GRID_AUTO_STATUS = false`, run through a module mock on the after tree, 500 seeds at bench pace): **all 500 event logs equal the base's**; the gate changes are still made (473 of them), nothing is put on. So the whole difference is this lane's rule.
* **Ablation 2, the pool** (a scratch copy of the after tree in which the layer shows Double MP but the pool is not doubled, 500 seeds at bench pace): **all 500 event logs equal the after tree's**, and every outcome and sum equals the base's. So the doubled MP itself changes nothing in these fights; the log differs from the base by the status event alone. (Run at bench pace only.)
* **The other eleven chapters.** Wearing none of the three grids: Bahamut (the Bevelle build), Leblanc and the experimental Leblanc (Chapter VI's Chateau build), Ixion and Djose and the Tourist Trap (the Djose build), Valefor and Besaid (the Besaid build) and Chapter XIII (its shipped kit puts all three girls on Valiant Lustre): byte-identical on 12 seeds. Wearing Tempered Will on Yuna but never crossing its gates in the intended play: Chapter V, the Experiment (Masterpiece Theatre), Chapter XV and Angra Mainyu: 0 gate changes by any girl in 12 seeds, 12 of 12 logs equal each. **At 500 seeds (bench pace, run after the first version of this note) all eleven are byte-identical too: 5,500 of 5,500 event logs equal, base against after**, rows in 5.2a.

### 5.4 What the measurement cannot show

A **human player** is not the autopilot: one who changes Yuna's dress along Tempered Will's green gate on purpose (Double HP) gets the doubled maximum HP, which the intended line never does. That path is proved on the engine (section 3), not measured in a fight. Highroad Winds' SOS Haste and Downtrodder's Double HP are not worn by any build, so no chapter can show them.


## 6. Disclosures, in player words

**Who sees it, and does a human player choosing those grids see it?**

* **Tempered Will (Yuna, in the Chapter V preset and the chapters built on it).** Anyone who changes Yuna's dress along a link that goes through the **red gate** sees "Max MP x2" appear on her (announced like any status, with the buff cue) and a bar twice as long, from that Change on; through the **green gate**, "Max HP x2" and a doubled HP bar, the girl at full HP staying at full and a wounded one keeping her share. A Dispel does not take it; a Stamina Tonic does not stack on it (the game has one bit for Double HP). **A human player sees this the first time she makes such a Change**; nothing makes it happen unasked, and a player who never changes Yuna through those gates never sees it. In the **intended play** it happens in Chapter XI (Yuna's Change out of Itchy goes through the red gate) in 213 of 500 fights at bench pace, 220 at human pace and 233 at Active pace, and changes **no outcome, no turn count, no minute and no KO** in any of them (section 5); in every other chapter the intended play does not cross the gates.
* **Highroad Winds (SOS Haste) and Downtrodder (Double HP): no human player sees them in the shipped game.** No build wears either, and no screen lets a player pick a girl's grid, so a player cannot choose them today. The rule is built, proved on a real engine (Highroad Winds' fourth gate puts the row in and a blow under a third turns Haste on; Downtrodder's three gates double the maximum) and switched on, waiting for a build or a screen that puts one of them on a girl.
* **The seven grids the engine lacks** (Mounted Assault, Selene Guard, Helios Guard, Shining Mirror, Wishbringer, Peerless, Last Resort): nobody sees anything; they are not in the build (section 1).
* **A girl who starts a battle with gates already crossed** (only a full carry, Chapter XV's links 2 and 3, arrives with any) is built with the pools doubled; the Chapter XV build wears Tempered Will on Yuna, but the intended play does not cross its gates there, so none of the 12-seed Chapter XV logs differs.
* **What did not change:** the grids' colours, the Spherechange wheel, the party-prep and pause strips (they read the data's node count and colours), the stat bonuses of every grid, and every grid's gate pay-off other than these rows.

## 7. Open items and decisions for Bailey

1. **The seven grids the engine lacks** (Mounted Assault, Selene Guard, Helios Guard, Shining Mirror, Wishbringer, Peerless, Last Resort) are real rows of the game's data and the mechanism is ready, but a grid is content: adding the registry entries (a name, the card's layout, the plate number, where it is obtained) is a hard rule 10 decision. Recommendation: add them with the next grid or menu lane that has its own mockup, from the grids lane's card export (`GARMENT_GRID_LAYOUTS` keys are our ids; the plate number and the card are already in the note); nothing else in the engine has to change.
2. **The order inside the dress change's rebuild is read, not run** (section 2): the maximum doubles, and HP and MP scale to it, in the very change that crosses the gate. If a live look (a Tempered Will girl at full HP crossing the green gate: does her bar stay full?) showed the game puts HP back before the layer is merged, the fix is one line in `spherechange.ts#refreshDerivedStats` (compute `held` from the rows she held before the change) and the tests that pin it say so.
3. **Conditions 7, 101 and 102** (gates 1+2+3; every dressphere node worn; both) are not used by any of the 64 plates, so the engine treats "every node worn" as false and condition 7 follows the kernel; if a future plate used them, the engine would need to track visited nodes (it tracks dresspheres worn). Pinned by `parity-ffx2-grid-status-rows.test.ts`.
4. **Gate colours are the grids lane's labels** (1 red, 2 green, 3 yellow, 4 blue is [inferred] and not applied everywhere; Tempered Will's red = gate 1 = Double MP and green = gate 2 = Double HP is the layout's own table and agrees with the data's pre-existing "Double HP on green, Double MP on red"). If the artwork look flips a colour, the layout tables change and nothing in this lane does.
5. **First browser look:** nothing was looked at in a browser (a status icon for Max HP x2 / Max MP x2 comes from the existing status cue table; Highroad Winds' Haste uses the existing Haste icon). Look at a Tempered Will girl crossing the red gate before a build that makes it likely ships.
6. **A violation of the lane's own rules, disclosed:** an early test command put `--experimental.fsModuleCache` before the file name, so vitest took the file name as the flag's value and ran the whole suite on 2 workers for about four minutes until the process was stopped by its PID; no result of it was used. The rest of the lane's runs name their files first.
