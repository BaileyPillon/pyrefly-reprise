## The two art contracts (what the art agents drop in)

Both go in the figure's own folder, with the usual sidecar (`<name>.json`: `width`, `height`, `baselineY`, `scale`, `facing`,
same as every other pose), and are picked up from `public/art/manifest.json` (regenerated by `npm run art:manifest`, which the build
and the deploy already run). A painting the manifest does not list is never requested.

1. **`characters/<artId>/od-<abilityId>.png`** is the key painting for one Overdrive or Special. `<artId>` is the figure's art id
   (`tidus`, `auron`, `yuna-gunner`, `paine-warrior`, an aeon such as `valefor`, a multi-form boss `braskas-final-aeon-2`);
   `<abilityId>` is the ability's data id (Tidus: `spiral-cut`, `slice-and-dice`, `energy-rain`, `blitz-ace`, see
   `src/data/ffx/abilities/overdrive-*.ts`; FFX-2 specials and boss moves by their ids in `src/data/ffx2`). Any ability with a painting
   uses it, so a boss move works the same way. Several per figure are fine.
2. **`characters/<bossArtId>/telegraph.png`** is a boss's wind-up painting (FFX `mortiorchis`, `evrae`, `braskas-final-aeon-1`,
   FFX-2 `ffx2-bahamut`, Shuyin, ...). Enemies only.

## What is built

- `src/engine/KeySlots.ts` (new, 146 lines): the whole behaviour. Gates: BATTLE SPECTACLE is on (`BattleStage.fx.enabled()`, the
  port the splash and hit-stops already use) and `BattleStage.paints(id, pose)` is true (the figure's **own** painting, never a
  fallback). FFX-2 only: not while a command menu is open (see "Open questions", 1).
- **Key painting, FFX**: set at `action-start` (after the figure's usual opening pose is skipped), so the letterbox, the name slab, the
  push-in and the strike are all on it. No wind-up (`ready`), impact (`attack`) or follow-through (`follow`) painting is put over it.
  `action-end` returns the figure to idle as for every action.
- **Key painting, FFX-2**: the wind-up still leads; the painting goes up at the **apex**, the first blow landing: a lunge's contact
  (`impactAtApex`, where it replaces the impact painting) or the first hit, miss or heal of a spell (`damage`, `missed`, after
  `meetContact`). Once per action. `followThrough` stands aside while it holds.
- **Telegraph**: the `charge` beat the presenter already plays (zoom, vignette, banner) puts the painting up for that beat. Outside
  an action the boss goes back to idle when the beat ends; inside one, `action-end` does.
- **Added waits: none** in either game (tests compare the exact sleep lists). **REDUCE MOTION**: a single cut (`setPose(..., {
  immediate: true })`, no crossfade, one swap per slot per action).
- Pose plumbing (`BattlePresenterArt.ts`): `ENEMY_POSES` gains `telegraph` (chain `telegraph -> idle`, so with no painting it is the
  idle's own texture and `paints` is false); `resolvePoseMap` adds every `od-*` state the manifest lists, no fallback chain.
  `EventCtx.menuOpen` (optional, set by `BattlePresenter`) tells the beats a menu is open. `BattlePresenterBeats.ts` calls the module
  at `action-start`, `action-end`, `damage`, `miss` and `charge`; `KeyPoses.ts` consults it so the impact and follow paintings do not
  override the key painting.
- Costs to know: every `od-*` painting of a figure is loaded with its other poses when the figure is staged (the same eager load the
  other poses get); a 2x master (`od-x@2x.png`) works through the existing art tier.

## Open questions for the driver / Bailey

1. **The FFX-2 menu rule** (the brief: "never while an FFX-2 menu is open") is implemented literally, as the exported constant
   `FFX2_SUPPRESS_WHILE_MENU = true` in `KeySlots.ts`: with an FFX-2 command menu open (at the move's open, or at its apex) both slots
   stand aside and the move plays as today. Under Active ATB, and under Wait's 0.5 s split, a menu is open for much of the fight, so
   in FFX-2 the paintings will show in part of the actions only (in the scripted Chapter IV runs, 1 of 7 Bahamut actions had a menu
   open, but a human at the controls keeps one up far more). The slots do not touch the camera, so the rule may have been meant for
   shots; if so, flip the constant to `false` (one line; `tests/unit/engine/r37-key-slots.test.ts` pins the current rule in two
   cases). Needs Bailey's word.
2. **Telegraph is beat-only** (about 1 s: the zoom, the banner, `TIMING.charge`; a menu that opens during the beat does not cut it short,
   the FFX-2 rule is read once, at the beat's start). A painting that holds until the boss fires would
   need the painting to survive the boss's other actions and `telegraphEnd`; it is a small follow-up if Bailey wants the boss to
   stay in the wind-up until the blow.
3. **FFX-2 "Special"** is any ability whose id has an `od-<id>` painting for that dressphere figure, not only the `SPECIALS`
   names the splash uses. Name only the ones that are painted.
