## 2. Step 0: the merge, and what the game does with a possessed copy's aeon

`418ca7ac9` merges the script-command-locks lane (`origin/re-parity-rc10-ffx-script-command-locks`, tip `b16e2e55b`, `SCRIPT_COMMAND_DISABLES` OFF) onto r54. `formation-commands.ts` auto-merged onto r54's design (`greyDisabledRows` keeps a switched-off command's rows and marks them `enabled: false` with no reason); only `docs/CONTRACT-CHANGES.md` conflicted (both entries kept, newest first).

**The question: is an aeon whose availability byte is 0 drawn greyed or skipped? Drawn greyed.** [R, Ghidra GETs on 127.0.0.1:8089 this lane]
- The Summon list is built by 0x00785410, `case 5`: for each slot 0 to 0x11 it adds the slot when `Chr+0x10` is non-zero (the character exists in the battle) and `pp_BtlIsAeon(slot)` holds, with the three Magus Sisters collapsed into one 0x30FF entry. It tests **nothing else**: not HP, not the recovery count, not the availability byte `Chr+0xDD4`.
- The draw loop 0x008A49B0 resolves each entry (the resolver call at 0x008A6708, to 0x0089ACA0) and skips it only for `-4` (the -4 compare at 0x008A6712) or the padding id 0xFF; any other negative result is drawn with the flag (read as grey, `FFX-G11` 4.1).
- For an aeon id (class 0) the resolver's disabled test 0x0079A5B0 calls 0x0079A080: HP above 0, **`Chr+0xDD4` non-zero**, `Chr+0xDCD` zero (left the battle) and **`Chr+0x6D8` zero**; any failure answers unavailable, the resolver -1. **`Chr+0x6D8` is one of the four tests; what writes it is still unknown** (`FFX-G11` open question 1, `FFX-G07` open question 8), so no behaviour is built on it.
- So the possessed copy's `setCommandDisabled(1, <its aeon>, 0)` leaves the aeon **on the list, drawn greyed, refused on a confirm**. The Grand Summon command (0x3118) opens the same list 5, so its picker shows the same greyed entry.
- Built (`72c062da3`, switch `SCRIPT_COMMAND_DISABLES` still OFF): in Chapter III's five possession links the copy's aeon stays on Yuna's Summon list greyed **with no reason** and in Grand Summon's picker as a greyed entry (`pickerParams.ts`: `enabled: false`; `YunaGrandSummon.ts`: a greyed row, the cursor rests on it, a confirm does nothing); the submit is still refused with the turn kept open, and the default roll still skips it. The words "Taken by Yu Yevon" are not used (`engine/tactics/lookup.ts#onLastSummoningBoard` keys on them; a test pins that Chapter III never looks like that board with every switch on). The lane's tests follow r54's greyed-row design. The Last Summoning is unchanged (it already greys its taken aeons with those words).
