## Note on methodology (read before trusting the smoke result)

The interactive browser pane available to this session was shared with other concurrently
running agent sessions against the same live origin (tabs were re-fronted mid-task by another
session, and `localStorage` under `pyrefly-reprise:save:v1` had been left holding another
session's Chapter IV Bahamut party-prep state). A first pass of real-input testing in that
shared pane appeared to show two problems — the Chapter I cutscene freezing on the line
"Yuna: No. Not this time.", and the CTB HUD never mounting (`display: none`, turn stuck at 0)
after reaching battle. Both were investigated and **not reproducible** in an isolated,
single-purpose Playwright context (its own browser process, its own storage, GPU-rendering
mode as required): the same real-input sequence (title → chapter select → party prep → start
battle → repeated real `Enter` key presses through the full cutscene, no debug skip) completed
cleanly, with the HUD rendering (`display: block`) once battle actually started. The
shared-pane result is attributed to cross-session interference (a hijacked tab, and once,
deliberately, this session clearing shared `localStorage` to get a clean run — noted here
because it could have reset another concurrent session's save data in that same browser
profile) rather than a defect in build 8f48237. The isolated-context run is the evidence of
record; the shared-pane run is not.
